# Documentation Style

> **In short:** lead with the point, keep it short, and let structure do the work.

## Rules

| Rule | In practice |
|---|---|
| **Summary first** | Open with a one-line *In short* |
| **Brevity** | Cut every word that does not change the meaning |
| **Plain language** | Everyday words; jargon only when needed, and explained |
| **Tables for comparisons** | Options, owners, gains and costs side by side |
| **Short sections** | One idea each, under a clear heading |
| **Lists for steps and sets** | Numbered for order, bullets otherwise |
| **Bold for key terms** | Sparingly, so the eye can scan |
| **Say it once** | Link to the source instead of restating it |
| **British spelling** | Throughout |

## Decision records

An ADR reads in this order: *In short*, **Why**, **The decision**, **Adopting it**, **What follows** (gains and costs), and **Guardrails** where needed.
